## 3. Bug Catalog & Root Cause Repros

### BUG-R8-01 (CRITICAL REGRESSION): Grub Permanently Immobilized on Spawn in `ruins_fall` (BUG-56/57 Regression from T03)

* **Severity:** **CRITICAL** (Blocks raw new game progression from frame 0)
* **First Introduced:** Commit `a619fcc` (Task T03 by codex: *"BUG-56/57 + OVW-022: R1 collision, Tide Pod clear of the bed..."*)
* **Affected Component:** `tools/maps/rooms/ruins_fall.py` -> `data/maps/ruins_fall.json` -> `Player::update`
* **Repro Steps:**
  1. Launch fresh game with no debug room flags: `nundertale_modern.exe`
  2. Skip disclaimer, lore, and instructions, select default name "GRUB".
  3. Watch opening landing cutscene `r1_landing` and `r1_wake`.
  4. At tick 872, `r1_wake` completes and player control is restored at spawn `(323, 232)`.
  5. Attempt to press UP, DOWN, LEFT, or RIGHT.
  6. **Observed Behavior:** Grub does not move a single pixel. Player is permanently stuck in place. Tapping Confirm interacts repeatedly with `flower_bed` (`r1_landing_items`: *"Forty-seven kinds of flowers. Alphabetized. Were."*).
* **Root Cause Analysis:**
  In commit `a619fcc`, `flower_bed` in `ruins_fall.py` was altered from `"solid": False` to `"solid": True`.
  - Grub's new-game spawn is at `(323, 232)`. Grub's collision box is `[position.x + 5, position.y + 38, 28, 18]`, which evaluates to `x: [328..356], y: [270..288]`.
  - `flower_bed` bounds are `x: [224..416], y: [212..300]`.
  - Because `[328..356, 270..288]` is entirely enclosed within `[224..416, 212..300]`, Grub is spawned **inside a solid obstacle**.
  - In `Player::update` (`src/entities/Player.cpp`):
    ```cpp
    Rectangle candidateX = { position.x + move.x + 5.0f, position.y + 38.0f, 28.0f, 18.0f };
    for (const auto& obs : obstacles) {
        if (CheckCollisionRecs(candidateX, obs)) { collideX = true; break; }
    }
    ```
    Since Grub is already intersecting `flower_bed`, every movement vector in X or Y collides immediately (`collideX = true`, `collideY = true`), locking player velocity to 0.
* **Harness Diagnostics Proof:**
  Confirmed via standalone collision simulator `tools/playtest/test_sim.cpp`:
  ```
  Solid object: flower_bed at (224,212 192x88)
  New game start: 323, 232
  After 1 tick UP: 323, 232
  After 1 tick DOWN: 323, 232
  After 1 tick LEFT: 323, 232
  After 1 tick RIGHT: 323, 232
  ```
* **Recommended Resolution for Map Team:**
  In `tools/maps/rooms/ruins_fall.py`, change `flower_bed` back to `"solid": False` (or keep floor collision disabled with `"floor": True` and exclude floor props from `m_obstacles` in `OverworldScene::refreshDynamicObstacles`).

### BUG-R8-02 (COLLISION OBSTRUCTION): `floofy_badge` Inaccessible During R1a Detour

* **Severity:** **HIGH** (Prevents natural in-game pickup of Floofy's Badge)
* **Affected Component:** `tools/maps/rooms/ruins_fall.py` / `data/maps/ruins_fall.json`
* **Repro Steps:**
  1. Start in R1a (`ruins_registration`), bump locked turnstile to trigger `r1a_turnstile` (sets `ruins.floofy.left_landing = 1` and `ruins.r1a.turnstile_tried = 1`).
  2. Walk south to R1 Landing through `door_to_landing` (arrives at `(300, 140)`).
  3. Walk south toward the flower bed to pick up Floofy's Badge at `(368, 248)`.
  4. **Observed Behavior:** Grub is stopped at `y ≈ 174` by the north edge of `flower_bed` (`y=212`). Grub's interaction reach extends to `y=238`. Because `floofy_badge` is located at `y=248`, the interaction box cannot reach `floofy_badge`. Pressing Confirm only interacts with `flower_bed` / `flower_dent` (`r1_landing_items`).
* **Root Cause Analysis:**
  Direct side-effect of `flower_bed` being solid. `floofy_badge` was positioned at `(368, 248)` inside the flower bed graphics. With `flower_bed` solid, the player cannot step close enough to trigger the badge interaction box.
* **Recommended Resolution:**
  Resolved by fixing BUG-R8-01 (`flower_bed` solid: False).
